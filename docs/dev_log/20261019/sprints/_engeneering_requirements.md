# Engineering requirements — sprints 12 and 13 (2026-10-19)

Binding for **every story** in this day's sprints. It restates the rules briefly and says what they
mean for caching and search. It extends, and does not replace, the repo-wide
[`_engeneering_requirements.md` of 2026-10-15](../../20261015/sprints/_engeneering_requirements.md)
(dead code, violations evaluation, quality guards). On a conflict, the stricter wins.

| Principle              | Rule for this work                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TDD**                | Red → green → refactor, one story at a time. The failing Vitest test is committed with (or before) the code that fixes it. A user-visible behaviour (search suggestions, results paging, a cached page loading) is not done until a Playwright test drives it. A bug found later gets a reproduction test first.                                                                                                                                                                                                             |
| **SOLID**              | _SRP:_ the cache stores and expires, it never knows GraphQL; the client transports, it never decides what is cacheable; a view renders, a composable fetches. _OCP:_ caching is added to `GraphqlClient` as an opt-in per call, with no `if (query === …)` in the client. _DIP:_ the client receives its cache by injection (`GraphqlClientOptions`); the search code gets the client from `useShopContext()`, never from a deep import. _ISP/LSP:_ a consumer that does not pass cache options sees no change in behaviour. |
| **DRY**                | One cache implementation (core). One search query document, one `SearchBox`, one `SearchView`. Pagination limits and debounce values are named constants defined once. No copy of any of them in `peroxid`.                                                                                                                                                                                                                                                                                                                  |
| **Clean code**         | Small functions with intention-revealing names, early returns, no boolean-flag parameters (use an options object or two functions), no commented-out code. Comments state constraints the code cannot show (e.g. why a mutation clears the cache). ESLint, Prettier and `vue-tsc` are the bar.                                                                                                                                                                                                                               |
| **No overengineering** | Only what the acceptance criteria need. No persistence layer (memory only), no cache-policy DSL, no generic "search provider" interface, no facet engine, no state library. Anything not listed in a sprint's _In scope_ goes to its _Deferred_ list and is not built.                                                                                                                                                                                                                                                       |

## Definition of done (per story)

1. Tests were written first and are green; the new code is covered.
2. `npm run lint`, `npm run type-check`, `npm run knip`, `npm run test:coverage` and `npm run build` are green in each repo touched (core coverage stays ≥ 90%).
3. No new dead code, `any`, or suppression without a one-line reason.
4. The behaviour is proven at the outermost layer it touches (browser for UI).
5. The day's `status.md` records what was done and any debt added.
